# Testing Actools BS5

## Isolated GitHub runtime checks

The `Drupal runtime and browser tests` workflow builds fresh Drupal 11.4.10
projects with core-dev in GitHub-hosted temporary directories. It runs Kernel
and Functional suites on PHP 8.3 and 8.4 with SQLite; the Functional server binds
to loopback only. No production database, BOA credentials or live-site test
helpers are used. Read each job's result and retained reports before accepting
a revision. Source checks are a separate workflow.

LayoutBuilderIntegrationKernelTest exercises all six native sections through
core Section/SectionComponent rendering, serialized settings, preview attributes,
block ordering and cache metadata. UserActionsCacheabilityTest switches viewers
over warm entity render caches and checks both allowed and denied action output.

The browser job installs pinned Playwright 1.64.1 in an isolated temporary
directory and tests the committed CSS in Chromium at 320, 375, 768 and 1440px.
It covers ordinary image fields, captioned text images and Layout Builder-style
columns, including aspect ratios and small authored widths. This is an asset
test against representative HTML, not a claim of live Drupal drag/drop coverage.
The same job reads the real page template's skip-link classes and checks keyboard
visibility and activation using the bundled Bootstrap CSS.

To run the browser fixtures locally with Playwright installed:

```sh
php tests/browser/build-token-fixtures.php /tmp/actools-token-fixtures.json
ACTOOLS_TOKEN_FIXTURES=/tmp/actools-token-fixtures.json npx playwright test --config tests/browser/playwright.config.cjs
```

The card-contrast tests use CSS generated by the actual PHP token builder for
default, pale and dark brands. They calculate contrast from browser-computed
colours for normal, hover and focus states in light/dark mode at phone/desktop
widths, requiring at least 4.5:1 without rounding the threshold.

The complete future acceptance sequence is in docs/IMPROVEMENT_PLAN.md.

The test pack distinguishes source/asset checks from actual Drupal rendering.
A skipped check is not a pass.

## Optional Topic starter

The runtime workflow also discovers `TopicStarterRecipeKernelTest` and
`TopicStarterEditorFunctionalTest`. They apply the actual optional recipe in
disposable Drupal installations, exercise its real fields/forms and Layout
Builder sections, and check reference access, warm caches, edits and formatted
text. Read the run results; adding a test is not evidence that it passed.

Heading regressions exercise deferred field-access callbacks, denied output and
warm render caches across viewers with the same permissions. The image-delivery
Kernel suite renders full Resources and text/image blocks, creates actual GD
derivatives, and checks proportional scaling, small-image handling and links to
the original uploads.

`topic-blocks.spec.cjs` checks the committed component CSS against representative
markup at phone/tablet/desktop sizes and in a narrow column on a wide screen.
It covers container-based stacking, whole-image aspect ratios and card-link
keyboard focus. Kernel/Functional coverage exercises the actual Twig integration;
the CSS fixtures do not simulate authenticated drag/drop editing.

A separate Chromium job installs the real recipe on a disposable Drupal site
and signs in as an editor with restricted permissions. Through the actual Layout
Builder interface it creates and edits both custom block types, uploads an image,
selects Resources, reorders blocks with core's keyboard Move form, saves and
reopens the layout. It checks anonymous output twice and confirms another Topic
retains the shared layout. Failure artifacts include screenshots, traces, HTML
and server logs. This job binds only to loopback and never contacts a live site.

See [PAGE_BUILDING.md](docs/PAGE_BUILDING.md) for manual acceptance, installation
and backup requirements. BOA site Verify and live layout editing remain separate
operator checks.

Publishing regressions also exercise the optional plain-text figure caption
and resource kind/level fields through native formatters, including empty and
denied output and cache metadata. Image-item regressions cover direct and
deferred denial, hidden image displays and alternating viewers over warm
caches; denied items must leave no image field wrapper, figure or caption.
The real-site browser fixture includes a
complete Surface tension Topic with separately named resource groups. Its
desktop and phone screenshots are retained in the
`layout-builder-editor-browser` artifact for visual review; an assertion pass
alone does not certify the appearance. The static specimen in
`docs/preview/topic.html` is a separate reference using the same committed CSS.

Resource-download Kernel regressions retain the native file-link render array,
checking descriptions, friendly fallbacks, file types/sizes, escaping, whole-field,
formatter-item and nested-link access, warm viewer caches and file/node edits.
Unrelated file links keep their normal rendering. The browser fixture opens
real PDF/DOCX Resource pages and fetches the actual files, checking their labels,
MIME types, sizes and signatures. It retains desktop and phone Resource captures.

Browser asset regressions also check text-first cards with mixed image/no-image
content, figure/caption alignment for small and large diagrams, and wrapping
download information in light/dark modes, on phones and in print media.

## Generic Lesson integration acceptance

`GenericLessonAssetsKernelTest` exercises the optional `libraries-extend`
integration through core asset discovery, rendering, caching and AJAX. The
theme CI runs it without installing Generic Lesson; a parsed module-library
fixture checks the extension without shipping a fake module that could shadow
the real one. The test also verifies normal theme assets with no module fixture.

The separate `tests/browser/generic-lesson-ui/` suite requires the actual
**Generic Lesson 2.1.2** package, Paragraphs, Entity Reference Revisions and the
local MathJax **3.2.2** distribution. These external module files are not bundled
in the theme. The ordinary asset-browser job deliberately excludes this suite;
it cannot establish real-module integration from the theme repository alone.

Use a disposable Drupal 11.4.10 project with Drush, this theme and Generic
Lesson installed at their normal custom extension paths. Install/enable
Generic Lesson using its package's instructions. From that project's root,
prepare the local maths assets and fixture:

```sh
export ACTOOLS_GL_PROJECT="$(pwd)"
export ACTOOLS_GL_DRUSH="$ACTOOLS_GL_PROJECT/vendor/bin/drush"
export ACTOOLS_GL_THEME_FIXTURE=1
export ACTOOLS_GL_BASE_URL=http://127.0.0.1:8894
export ACTOOLS_GL_FIXTURE="$ACTOOLS_GL_PROJECT/lesson-fixture.json"
export ACTOOLS_GL_BROWSER_OUTPUT="$ACTOOLS_GL_PROJECT/lesson-browser-results"
export ACTOOLS_GL_EDITOR_PASSWORD="$(openssl rand -hex 24)"
export ACTOOLS_GL_ADMIN_PASSWORD="$(openssl rand -hex 24)"
npm install --prefix lesson-mathjax --no-save --package-lock=false --ignore-scripts mathjax@3.2.2
mkdir -p web/libraries/mathjax
cp -R lesson-mathjax/node_modules/mathjax/es5 web/libraries/mathjax/
"$ACTOOLS_GL_DRUSH" --uri="$ACTOOLS_GL_BASE_URL" php:script web/themes/custom/actools_bs5/tests/browser/generic-lesson-ui/seed-lesson-site.php
"$ACTOOLS_GL_DRUSH" --uri="$ACTOOLS_GL_BASE_URL" cache:rebuild
```

The guarded seed changes the disposable site's theme/settings, creates test
accounts and content, and refuses to run twice. The native fixtures include
guided/continuous reading, all seven quiz formats, a real Layout Builder
override, figures, maths, public disclosures and a normal-page control. The
suite changes only fixture presentation settings and resets the fixture
learner's records when testing saved answers. Do not use an existing live site.

Install pinned Playwright tooling outside the theme, then run server and browser
within the same process/network environment:

```sh
npm install --prefix lesson-browser-tools --no-save --package-lock=false @playwright/test@1.64.1
export NODE_PATH="$ACTOOLS_GL_PROJECT/lesson-browser-tools/node_modules"
"$ACTOOLS_GL_PROJECT/lesson-browser-tools/node_modules/.bin/playwright" install --with-deps chromium
(
  cd "$ACTOOLS_GL_PROJECT/web"
  php -S 127.0.0.1:8894 .ht.router.php > "$ACTOOLS_GL_PROJECT/lesson-server.log" 2>&1 &
  lesson_server_pid=$!
  trap 'kill "$lesson_server_pid" 2>/dev/null || true' EXIT
  for attempt in $(seq 1 20); do
    if curl --fail --silent --output /dev/null "$ACTOOLS_GL_BASE_URL/user/login"; then break; fi
    sleep 1
  done
  curl --fail --silent --output /dev/null "$ACTOOLS_GL_BASE_URL/user/login"
  cd themes/custom/actools_bs5
  "$ACTOOLS_GL_PROJECT/lesson-browser-tools/node_modules/.bin/playwright" test --config tests/browser/generic-lesson-ui/playwright.config.cjs
)
```

Set `ACTOOLS_GL_CHROMIUM` only when using a separately installed compatible
Chromium executable. Screenshots, failure traces and a print PDF go to the
explicit output directory. The browser checks cover theme palette overrides,
text/control contrast, keyboard anchors, actual Toolbar geometry, narrow
viewports, answers/progress, Layout Builder, editor loading and print privacy.
This is Chromium coverage, not a complete assistive-technology or browser matrix.

The maintained lesson stylesheet can be rebuilt independently:

```sh
npm run build:css -- --entry=theme/generic-lesson.theme
npm run check:css -- --entry=theme/generic-lesson.theme
```

## Checks without Drupal

In a Git checkout, run the packaging/static audit against an exported tree so
the repository's own .git directory is not mistaken for shipped release content:

```sh
theme_test_export="$(mktemp -d)"
git archive HEAD | tar -x -C "$theme_test_export"
python3 tests/tools/actools_bs5_static_audit_tests.py "$theme_test_export"
```

For an extracted release archive with no .git directory, use the direct command
below. The packaging gate deliberately continues to reject .git in releases.

```sh
python3 tests/tools/actools_bs5_static_audit_tests.py .
python3 tests/tools/test_layout_regressions.py
node --test scripts/css-compat.test.mjs
```

The static runner requires Python 3 and PyYAML; Node is used for JavaScript
syntax checks. Missing PHP is reported as an explicit skip. A release gate can
require PHP and promote advisories:

```sh
python3 tests/tools/actools_bs5_static_audit_tests.py . --require-php --strict-advisory
```

Demo image examples assume the documented `themes/custom/actools_bs5` location;
the path advisory does not refer to production field images. Examples may need
adjustment for other installations.

## Drupal Kernel and Functional tests

Use a disposable Drupal 11 test site with core-dev/PHPUnit and a configured test
database. Install the theme at a normal theme path. Copy the test-only helper:

```sh
cp -a tests/drupal-module/actools_bs5_test /path/to/drupal/web/modules/custom/
```

From the Drupal web root, with the test database and base URL configured:

```sh
mkdir -p sites/simpletest/browser_output
../vendor/bin/phpunit -c core/phpunit.xml.dist modules/custom/actools_bs5_test/tests/src/Kernel
../vendor/bin/phpunit -c core/phpunit.xml.dist modules/custom/actools_bs5_test/tests/src/Functional
```

ComponentRenderingRegressionTest renders real component templates for hostile
and legacy input and uses SDC smoke paths for ordinary metadata-valid input.
It covers URL output, filtered rich HTML, safe summaries, native image sources,
card links, navbar targets, block labels and carousel content/IDs. The token
lifecycle suite invokes the actual writer to test expired/recent/current files.

A convenient component-test wrapper is also included:

```sh
python3 tests/tools/test_component_regressions.py --drupal-root /path/to/drupal/web
```

See that script's `--help` for accepted project/phpunit arguments. It reports a
skip when a PHP/Drupal test environment is absent.

## Manual acceptance

On a test copy: enable the theme, check ordinary nodes, login/forms, menus with
multiple levels, block titles and card links; change brand/font settings; verify
cache clearing; add/edit/reorder blocks in each of the six Layout Builder
sections; check phone/tablet/desktop widths, keyboard navigation and printing
of hidden answers. Full-width sections respect the outer Content container.

The shipped tests are not a substitute for this browser/Drupal acceptance.
The test helper is never auto-enabled and is not required in production.

## Header/navigation and discovery acceptance

A separate navigation browser fixture places actual branding and main-menu
blocks in Header plus a second menu instance in Footer. It runs on disposable
Drupal 11.4.10/PHP 8.4 sites with each core administration interface (Toolbar
and Navigation), using a restricted editor. It exercises parent navigation,
submenus, focus/Escape, width changes, fragment/history clearance, sticky off,
no JavaScript, theme colours/text sizes, print and Layout Builder dialogs.
Desktop and closed/open phone screenshots are retained per interface. These
fixtures do not establish compatibility with an uninstalled Gin or Canvas app;
the Canvas preview marker remains supported.

The optional discovery recipe has query/rendering and real form tests covering
title/summary matches, metadata filters, native cards, node grants and pager
counts, warm edits/unpublishing and negotiated-language output. It changes no
roles or Topic relationships. See docs/HEADER_NAVIGATION.md for site setup.

The Sass tree has pre-existing drift from some shipped Bootstrap/RTL bundles.
Compile the maintained navigation entries without republishing those bundles:

```sh
npm ci --ignore-scripts
npm run build:css -- --entry=theme/navigation.theme --entry=theme/sticky-header.theme
npm run check:css -- --entry=theme/navigation.theme --entry=theme/sticky-header.theme
npm run publish:css -- --entry=theme/navigation.theme --entry=theme/sticky-header.theme
```

The entry allowlist rejects arbitrary paths; existing source/candidate hashes
and selector-removal guards still apply. The source workflow compares these
compiled files byte for byte with the committed CSS. Unselected bundles retain
their shipped contents.
